# Правила обновления OPS Control без потери данных

Эти правила считаются частью архитектуры проекта.

1. Не менять Android applicationId:
   `ru.opscontrol.app`

2. Все APK/AAB обновления подписывать тем же release signing key.
   Если ключ подписи изменится, Android не установит новую сборку как
   обновление существующего приложения.

3. Никогда не удалять локальную SQLite базу при запуске новой версии.

4. Каждое изменение структуры БД оформлять отдельной последовательной
   миграцией:
   - v3 -> v4
   - v4 -> v5
   - и т.д.

5. Нельзя заменять миграцию командой DROP TABLE + CREATE TABLE,
   если таблица содержит пользовательские данные.

6. Перед крупным обновлением пользователь должен иметь возможность
   создать `.opsbackup`.

7. Перед полным импортом приложение само создаёт `pre_import`
   страховую копию.

8. Seed/demo данные добавляются только при первом создании БД
   (`onCreate`), а не при каждом запуске.

9. Новая версия приложения обязана уметь открыть БД предыдущей версии.

10. Перед публикацией обновления проверяется сценарий:
    старая версия -> данные -> установка новой версии поверх ->
    автоматическая миграция -> данные и фото на месте.


## Нагрузочные данные

Тестовые записи должны всегда иметь `is_test = 1`.
Обычный экспорт/backup не должен включать такие записи.
Перед реальной эксплуатацией тестовый набор удаляется отдельной функцией.
