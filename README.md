# OPS Control v9.5.5 — Simple Workflow

Цель версии: убрать лишние действия из повседневной работы инженера,
не теряя складской и документальной трассировки.

## Главное правило

Инженер работает действиями:

```text
увидел заявку
→ приехал
→ сделал
→ указал использованный материал
→ коротко написал, что сделал
→ закрыл
```

Внутренние номера документов, движения склада, партийные связи,
источник материала и подготовка акта выполняются автоматически.

## Главный экран

Главный экран сокращён до действительно частых действий:

- открытые заявки;
- маршрут;
- объекты;
- новая заявка;
- импорт утреннего отчёта.

Склад, документы, справочники и резервные копии спрятаны в компактные
разделы «Материалы» и «Настройки».

## Мой мобильный запас

В списке инженеров можно звёздочкой выбрать:

```text
Мой запас
```

Первый созданный инженер автоматически становится «моим».

После этого в карточке работы больше нет отдельного шага
«Откуда списать материал?».

Нажатие `+` в материалах сразу показывает:

1. мой мобильный запас;
2. ниже основной склад.

Далее только:

```text
материал → количество → Готово
```

## Закрытие работы

Обязательно только поле:

```text
Что сделали
```

Остальное рационально:

- причина пустая → `Не установлена`;
- результат пустой → `Работоспособность восстановлена`;
- замеры — по необходимости;
- фото — по необходимости;
- материалы — только если реально использованы.

## Акт списания

Если:
- по заявке были материалы;
- реквизиты организации уже заполнены;

после закрытия работы запись акта списания подготавливается автоматически.

Инженер не видит дополнительных диалогов.

Если реквизиты ещё не настроены, работа всё равно закрывается нормально.
Печатный акт можно подготовить позже из истории.

Повторное нажатие «Акт списания» открывает уже существующий документ,
а не создаёт дубликат.

## Закупка

Внутренняя заявка на закупку больше не требует предварительно заполнять
бухгалтерские реквизиты организации.

Реквизиты нужны только когда требуется юридически оформленная печатная
форма.

## Внутренние перемещения

Номера перемещений сохраняются в базе для аудита, но в обычном интерфейсе
инженеру не показываются как отдельная бюрократическая процедура.

Интерфейс говорит просто:

```text
Выдача со склада
Возврат на склад
```

## Что осталось строгим

Не упрощались критичные проверки:

- нельзя списать больше доступного остатка;
- нельзя вернуть больше запаса инженера;
- складские изменения выполняются транзакционно;
- источник материала сохраняется;
- партии сохраняются;
- документы не помечаются подписанными без подписи;
- backup сохраняет все данные.

## Миграция

SQLite:

```text
v14 -> v15
```

Добавлены только настройки простого режима:

```text
simple_workflow = 1
default_engineer_id
auto_prepare_writeoff = 1
```

Рабочие таблицы и существующие данные не пересоздаются.
